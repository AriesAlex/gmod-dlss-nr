# gmod-dlss-nr

Переносимый Windows-комплект GMod RTX с native DLSS RR + NR и отдельным старым SR + NR bridge. Рабочий поток и промпт полного развёртывания находятся в [README.md](README.md).

## Источники истины

- `scripts/deploy.ts` владеет развёртыванием, профилями и проверкой файлов. `scripts/lib/engine-patches.ts` применяет только точные преобразования из `config/engine-patches.json`.
- `config/artifacts.json` закрепляет release ZIP и SHA256. `config/payload-files.json` закрепляет остальные поставляемые файлы. При изменении payload обновляй соответствующие хеши и происхождение.
- `config/base` содержит начальные настройки, `config/profiles` — параметры RR/NR конкретного профиля. Не дублируй профильные ключи в базовых файлах.
- `sources/*` — закреплённые upstream submodule. `patches/*.patch` — полный источник наших C++-изменений, включая untracked новые файлы. `bun run sources:prepare` приводит чистые копии к этому состоянию, `sources:verify` проверяет точные файлы и вложенные gitlinks.
- Локальная Lua-правка находится в `payload/common/garrysmod/addons/remixbinary/lua/autorun/cl_rtx.lua`. Сравнивай её с `sources/fixes/garrysmod/garrysmod/...`, а не со случайной старой копией мода.
- `tools/hl2rtx-mount` владеет объединением HL2 RTX ресурсов, ссылками, mount.cfg и USDA. Не дублируй его логику в установщике; происхождение исходников описано в его `UPSTREAM.md`.

## Работа с игрой

1. Сначала прочитай текущие исходники, манифесты и фактическую конфигурацию цели. Различай файлы комплекта, установленную модифицированную игру и Steam-оригинал.
2. Используй `setup` без `--apply` для плана. Полная установка идёт только в отдельную папку; Steam-оригинал служит источником. Не патчь неизвестные DLL по старым смещениям.
3. Не завершай игру автоматически. DLL, конфиги и аддоны целевой установки меняются только после её закрытия. Не вводи игровые команды, Lua-пробы и не управляй окнами во время игры без отдельного разрешения; свежие логи можно читать.
4. После установки выполни `verify`. Дождись запуска пользователем и загрузки карты, затем `doctor`. Подтверждай native NR по успешным EvaluateFeature-счётчикам, RR — по тому же запуску и его настройкам/ошибкам. Не выдавай загрузку DLL или компиляцию шейдеров за рабочие кадры.
5. Сохраняй пользовательские настройки, личные аддоны и посторонние изменения. Не включай данные игры, логи, снимки экрана, сгенерированные кэши и временные QA-скрипты в комплект.

## Изменения и проверки

Предпочитай простой итоговый код в правильном слое, без лишних состояний, обёрток и непроверенных fallback. Сначала докажи причину по исходникам, данным или реальному поведению. После рабочего результата проведи абляционный проход, удалив всё добавленное, без чего поведение и поддерживаемость сохраняются, затем повтори применимые проверки. После каждого изменения пересматривай diff как ревьюер. Юнит-тесты не добавляй.

Основные команды: `bun run typecheck`, `bun run verify:artifacts`, `bun run sources:verify`, `git diff --check`. Для установщика дополнительно проверь реальное развёртывание во временную отдельную папку, повторную установку, переключение профиля, сохранение настроек и отказ на повреждённом/неподходящем входе. Для C++ сначала выполни `bun run build:native -- -CheckOnly` или `build:legacy`, затем соответствующую сборку; обязательны свежие runtime-доказательства после установки.

В `sources/remix` прочитай его собственный `AGENTS.md` и нужный build skill. Используй MSVC 14.41; `SetupBuild` и Meson должны выполняться в одном shell. Два build-скрипта запускаются последовательно, поскольку обновляют общий payload manifest. Закрытые NVIDIA и legacy provider DLL не пересобираются из доступных исходников. Никогда не подменяй отсутствие исходников предположением о лицензии другого репозитория.

При изменении C++ обнови полный patch и payload согласованно. Исходники под patch намеренно dirty; не фиксируй их как случайные новые upstream pins. Сохраняй полный патч через временный индекс, не затрагивая чужой Git index, затем проверь его применение и обратное применение на закреплённой базе.

## Git и правила

Крупные ZIP, DLL и addon64 хранятся через Git LFS; `payload/archives` обязателен для восстановления mutable nightly. Готовые файлы в `payload` входят в комплект; не коммить промежуточные результаты сборки вне payload, node_modules и `.cache`. Remote отсутствует либо его видимость должна проверяться отдельно: не добавляй и не отправляй секреты, не печатай их значения. Публикация полного комплекта с закрытыми provider DLL требует отдельной проверки условий распространения и явного запроса на публикацию.

Правила в `AGENTS.md` добавлять только если пользователь явно просит сохранить что-то универсальное и долговременное; не заносить туда ситуативные договорённости текущей задачи.

«Работает» недостаточно. После того как довел до рабочего состояния, убедись, что решение встроено в код красиво и без временных подпорок. Если по пути пришлось оставить костыль или фоллбэк, потом обязательно добейся его удаления, даже если для этого надо явно попросить пользователя сделать связанное изменение.
